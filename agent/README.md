# 월급잇다 에이전트 0.4.0

문서 작업을 **원문 읽기 → AI 항목 정리 A → 필요한 항목의 PDF 보완 읽기 B → 원문 확인·문서 대조**로 제공합니다. A가 기본이며 B는 사용자가 선택한 확인 필요 항목에만 별도로 실행합니다. 계약서·근무기록·급여명세서·입금기록을 처리합니다.

현재 구현은 단일 사용자용 로컬 파일 저장소와 개발 화면입니다. 운영 인증·사용자 격리·DB·다중 프로세스 작업 큐는 구현하지 않았습니다. 고정된 1일 8시간·주 40시간 성인 표준 근무의 시급·월급 계산과 급여명세서 대조를 지원합니다. 세부 지원 범위와 검증은 [임금 기능 안내](PAYROLL.md)를 확인하세요.

## 실행

프로젝트 루트에서 Python 3.14 가상환경을 사용합니다. 의존성 설치가 필요하면 `uv sync`를 실행하고, OCR 준비는 [OCR 안내](dev/OCR.md)를 따릅니다. AI 추출·PDF 보완의 API 키·모델 설정은 `agent/.env`에서 읽습니다.

```powershell
.\.venv\Scripts\python.exe -m agent.dev.test_server --port 4190
```

- [원문 읽기](http://127.0.0.1:4190/ocr): PDF 업로드 → 로컬 읽기 실행 → 페이지별 텍스트와 읽기 방식 확인. 디지털 텍스트층을 먼저 사용하고 품질이 부족한 페이지는 OCR로 읽습니다.
- [AI 처리](http://127.0.0.1:4190/ai): 저장 원문 확인 → **AI 처리 실행**으로 기본 후보 A 저장 → 필요한 항목만 선택해 PDF 보완 읽기 B 실행 → 원문 확인 후 후보 선택·직접 수정·보류.
- [문서 대조](http://127.0.0.1:4190/compare): AI 분류 완료 문서 선택 → 독립된 비교 묶음·대상기간 확인 → 항목별 나란히 비교 → **확인한 값으로 비교** → 결과.
- [결과](http://127.0.0.1:4190/results): 계산 내역·대조·원문 근거·과거 결과.
- [확인 질문](http://127.0.0.1:4190/questions): 부족한 조건·필요 날짜 확인, 답변 후 재계산.
- [회사 문의](http://127.0.0.1:4190/inquiry): 확인한 사실로 초안 작성·수정·저장·복사.
- [자료 받기](http://127.0.0.1:4190/reports): 결과별 PDF와 선택 원본 ZIP.
- [쉬운 용어](http://127.0.0.1:4190/glossary): 문서 없이도 쉬운 한국어 설명과 예시 검색.


업로드·페이지 이동·로컬 읽기 완료만으로 AI를 호출하지 않습니다. **로컬 읽기와 자료 대조는 모델 호출 0회**입니다. A는 저장한 텍스트만 AI에 전달합니다. B는 별도 실행 시 **원본 전체 PDF를 OpenAI에 전송**하며 추가 API 사용량이 발생합니다. 선택한 항목만 판독하도록 요청하지만 전송 파일을 해당 항목이나 페이지만으로 잘라 보내지는 않습니다. 질문·설명·회사 문의·용어 조회·보고서 생성은 기본적으로 API를 호출하지 않습니다.

AI 문서 유형의 기본값은 `auto`입니다. 분류할 수 없거나 서로 다른 종류가 섞인 문서는 파일 분리 또는 유형 선택을 안내합니다. 직접 선택한 유형과 AI 판단이 다르면 성공 처리하지 않습니다.

## 저장과 재실행

기본 저장 위치는 `output/document-workspace/`입니다.

| 경로 | 내용 |
|---|---|
| `documents.json` | 직접 업로드한 문서의 메타데이터 |
| `uploads/` | 업로드 PDF |
| `cases/` | 문서별 저장 원문·A/B 후보·사용자 선택 이력·기존 사례 입력과 결과 |
| `comparisons/` | 독립된 비교 묶음의 자료 선택·확인 입력·결과·이력 |
| `jobs/` | 단계별 작업 상태·사용량·OCR 결과 연결 ID |
| `artifacts-and-checkpoints/` | 비공개 체크포인트와 PDF·ZIP 산출물 |

호환용 `case.ocr` 키에 로컬 읽기 결과를 저장합니다. `pages`는 페이지별 원문 텍스트, `ocr_pages`는 행과 OCR인 경우의 인식 신뢰도입니다. `page_methods`는 페이지별 `pdf_text / python_ocr`, `source_method`는 `pdf_text / python_ocr / mixed`입니다. 디지털 텍스트에는 OCR 신뢰도 수치를 만들지 않습니다.

기본 후보는 `case.extraction_a`·`extraction_a_revision`, PDF 보완 결과는 `case.supplements`에 따로 보존합니다. 현재 사용할 항목은 `case.extraction.fields`, 페이지·인용 근거는 `case.extraction.evidence_catalog`에 있습니다. `candidate_selections`·`candidate_selection_history`에는 선택 후보 또는 직접 입력값, 원본 해시·A 버전·작업·실행 ID와 확인 이력을 남깁니다. B 완료만으로 현재 항목이나 대조 입력을 교체하지 않습니다.

추출 항목에는 원시값 `raw_value`, AI의 원래 제안값 `suggested_value`, 검사를 통과한 값 `normalized_value`를 따로 저장합니다. 검사 상태 `validation_status`는 `valid / needs_review / missing`이며 `validation_reasons`에 사유를 남깁니다. 상태와 사유는 Python 검사기가 결정합니다. AI가 주장한 `source_quote`·`source_page`는 검토용으로 보존하지만, 근거 검사에 실패하면 `evidence_refs`는 비웁니다.

현재 추출 계약의 기본 `extraction_version`은 `1.2`입니다. A/B 방식·대상 항목·페이지별 출처를 공개 계약에 추가하되 계산 엔진은 `agent-0.4.0`, 추출 호환 버전은 `extraction-1.2`로 분리하고 공개 스키마·체크포인트 `1.0`은 유지합니다. 기존 `1.0 / 1.1` 결과와 성공한 저장 후보는 호환해 읽으며 사용자 확인은 계속 필요합니다. 기존 자료를 자동 재실행·재검증하거나 B를 자동 호출하지 않습니다. 호환용 기본값이 새 검사를 통과했다는 뜻은 아닙니다.

한 항목의 인용·숫자·단위·날짜 오류는 해당 항목만 검토 필요로 남기고 `normalized_value=null`로 저장합니다. 다른 정상 항목은 유지하고 이 오류로 AI를 자동 재호출하지 않습니다. 문서 유형·응답 구조·권한·원본 해시·저장 OCR 연결 등 전체 실행 조건의 오류는 작업 실패 또는 취소로 처리합니다.

A 작업은 호환용 `ocr_result_id`로 해당 문서의 저장 읽기 결과를 재사용하며 로컬 읽기를 다시 실행하지 않습니다. B는 A의 `needs_review / missing` 중 아직 사용자가 확정하지 않은 항목을 1~50개 선택해 실행합니다. 같은 문서·원본 해시·읽기 결과·A 버전에 연결된 후보만 사용할 수 있습니다. 로컬 읽기·A 재추출·유형 변경으로 기준이 바뀌면 이전 보완 후보와 선택을 이력으로 남기고 현재 적용에서 제외합니다. 초안은 기존 재추출 보존 규칙을 따르며 관련 대조 묶음은 다시 불러와 확인해야 합니다.

새로고침·서버 재시작 후 문서와 작업 상태를 복구합니다. 취소·중단 작업은 입력과 설정이 같을 때 누적 호출 예산을 이어받아 실행할 수 있습니다. 이미 시작된 A/B 요청은 취소해도 사용량이 발생할 수 있으며 취소된 결과를 자동 적용하지 않습니다. 같은 사례에서 여러 작업을 동시에 실행하지 않습니다.

문서 대조는 한 문서를 대표 사례로 삼지 않고 별도의 비교 묶음에 저장합니다. 묶음 안에서 값·대상 정보를 수정해도 원본 PDF와 저장된 AI 후보는 바뀌지 않습니다. 원본 재추출·유형 변경으로 자료 버전이 바뀌면 관련 묶음을 갱신 필요로 표시하며, 자료를 다시 불러와 확인해야 합니다. 과거 결과에는 실행 당시 기간·입력·자료 버전을 보존합니다.

문서 선택 전에 근로자·사업장·기간·임금 단위·검토 항목 수를 보여 줍니다. 확인된 이름·사원번호·사업장이 충돌하면 대상 정보를 원문과 대조해 바로잡거나 다른 문서를 제외해야 합니다. 정보가 없는 과거 추출은 비교용으로 보완할 수 있으며, 모든 새 묶음은 같은 대상의 문서라는 사용자 확인을 거칩니다. 월급/시급은 자동 환산하지 않고, 근무기록의 시간과 명세서의 실근로시간·유급/지급기초시간을 구분합니다.

## 백엔드 연결 계약

`run_task(task, ports=..., settings=...)`는 A 항목 추출·B PDF 보완·대조·설명·보고서를 실행합니다. 로컬 텍스트/OCR 읽기는 별도 `recognize_document`에서 처리합니다. `ExtractionInput.extraction_method`는 기본 `text` 또는 `pdf_supplement`이며 B의 `target_fields`는 1~50개입니다. A/B 모두 연결된 읽기 결과가 필요하며 `ocr_result_id`가 없으면 `OCR_REQUIRED`로 실패합니다. B는 A 실행 전체 실패를 자동 우회하는 경로가 아닙니다.

운영 연결은 [AgentPorts](ports/runtime.py)의 구현이 필요합니다. 호환용 `read_ocr(context, source, ocr_result_id)`는 접근 권한과 source ID·문서 ID·버전·해시·읽기 결과 ID를 검증하고 저장 텍스트와 페이지별 읽기 방식을 반환해야 합니다. API에서 받은 임의 텍스트를 신뢰된 결과로 취급하지 않습니다. B 원본 전송 전에도 권한·버전·해시·취소 여부를 검사합니다.

체크포인트·누적 모델 호출 예산·취소·실행 소유권을 보존하고, 백엔드가 최종 결과의 저장·최신성·접근 권한을 확정해야 합니다. 로컬 `LocalFilePorts`는 운영 권한·동시성 보장을 대신하지 않습니다.

공개 JSON Schema는 모델 호출 없이 생성합니다.

```powershell
.\.venv\Scripts\python.exe -m agent.export_contracts --output agent/contracts
```

## 검증 범위와 한계

디지털 텍스트층 근거는 `text_match`, OCR 근거는 `ocr_unverified`, B PDF 판독 근거는 `vision_unverified`입니다. `text_match`도 저장 텍스트와 인용이 일치한다는 뜻이며 원본 화면·문서 내용의 정확성이나 사용자 확인 완료를 뜻하지 않습니다. A/B 값이 같아도 자동 확정하지 않습니다.

`valid` 후보도 사용자 확인이 필요합니다. A/B의 값·단위·페이지·인용을 확인한 뒤 형식 검사를 통과한 후보를 선택하거나 직접 수정하고, 판단하기 어려우면 보류합니다. 후보 선택 후에도 대조 자료를 다시 불러와 입력을 확인해야 합니다. 표는 행 번호나 금액이 같다는 이유만으로 대응시키지 않으며 항목명·날짜·거래 식별정보를 확인합니다. 필수 정보가 빠진 행은 금액만 입력해 정상 행으로 사용할 수 없습니다. 명세서 문제 행은 제외 후 수기 보완할 수 있고, B 완료만으로 누락 항목의 완전성을 인정하지 않습니다.

대조는 계약/명세서 단가, 근무/명세서 시간, 명세서 내부 합계, 명세서/입금, 계산 임금/명세서를 확인된 범위에서 비교합니다. W-01~05와 R-07은 표준 시급·월급 범위에서 지원합니다. 누락을 0으로 채우거나 전체 미지급액으로 단정하지 않습니다. 전체 조건이 충분할 때만 `gross_total`과 `scope_complete=true`를 제공합니다. [지원 범위](PAYROLL.md)를 참고하세요.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check agent
```

테스트용 공급자·합성 자료는 테스트 폴더에 격리되어 있으며 실제 앱에는 샘플 목록이나 가상 공급자가 없습니다. 상세 화면/API는 [로컬 작업실 안내](dev/README.md), 구현 범위는 [구현 상태](IMPLEMENTATION_STATUS.md)를 참고하세요.
