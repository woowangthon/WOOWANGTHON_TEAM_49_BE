# 원문 읽기와 A/B 항목 정리

**로컬 원문 읽기 → 기본 AI 항목 정리 A → 필요한 항목의 PDF 보완 읽기 B → 사용자 원문 확인** 순서입니다. A가 기본이고 B는 선택 실행입니다. 업로드·페이지 이동·작업 완료가 다음 AI 호출을 자동 시작하지 않습니다.

## 로컬 읽기 준비

프로젝트 루트에서 실행합니다.

```powershell
uv sync
powershell -File agent/dev/setup_ocr.ps1
.\.venv\Scripts\python.exe -m agent.dev.test_server --port 4190
```

Windows 준비 스크립트는 7-Zip으로 Tesseract와 한국어·영어 언어 데이터를 `tools/ocr/`에 설치하고 고정 SHA256을 확인합니다. 실행 파일·DLL·언어 데이터는 저장소 배포 파일에 포함하지 않습니다. 기존 설치는 `agent/.env`의 `AGENT_OCR_COMMAND`, `AGENT_OCR_DATA_PATH`로 지정합니다. `kor`·`eng`가 모두 필요하며 PDF 렌더링은 `pypdfium2`를 사용합니다.

## 1. 페이지별 로컬 원문 읽기

[원문 읽기 페이지](http://127.0.0.1:4190/ocr)에서 PDF를 업로드하고 읽기를 실행합니다. 모델 호출과 토큰 사용은 없습니다.

- 디지털 PDF의 텍스트층을 우선 읽고 레이아웃의 행·열 간격을 보존합니다. 금액·구두점·날짜를 임의로 고치지 않습니다.
- 글자 수만으로 텍스트층을 신뢰하지 않습니다. 이미지 포함 페이지, 숨김·투명·판독이 불확실한 텍스트, 회전·깨진 문자 매핑, 레이아웃 처리 중 문자·숫자 손실 등은 OCR로 전환합니다. 작은 로고를 포함한 디지털 페이지도 보수적으로 OCR 처리할 수 있습니다.
- 스캔·품질 부족 페이지는 기존 Tesseract `kor+eng`, `--psm 6`, 기본 300dpi로 읽습니다. 문서 전체에 한 방식을 강제하지 않고 혼합 PDF를 페이지별 처리합니다.
- `case.ocr.pages`에 텍스트, `ocr_pages`에 행과 OCR인 경우의 신뢰도, `page_methods`에 `pdf_text / python_ocr`, `source_method`에 `pdf_text / python_ocr / mixed`를 저장합니다. 키 이름 `ocr`는 호환을 위해 유지합니다. 디지털 텍스트에 OCR 신뢰도 숫자를 만들지 않습니다.
- 결과 ID·문서 ID·버전·원본 해시를 함께 저장합니다.

사용 가능한 디지털 텍스트만 있는 문서는 OCR 엔진 없이 읽을 수 있습니다. OCR이 필요한 페이지에서 설치·언어 데이터 문제는 `OCR_UNAVAILABLE`, 처리 실패·전체 빈 읽기 결과는 `OCR_FAILED`로 표시합니다. 이 실패를 유료 PDF 판독으로 자동 우회하지 않습니다.

## 2. 기본 AI 항목 정리 A

[AI 처리 페이지](http://127.0.0.1:4190/ai)에서 저장 원문을 확인하고 **AI 처리 실행**을 누릅니다. API 사용량이 발생합니다.

A는 저장한 텍스트만 AI에 전송합니다. `ocr_result_id`로 고정한 읽기 결과를 재사용하며 로컬 읽기를 다시 실행하지 않습니다. `auto`가 기본이며 문서 유형과 요약값·상세 행을 한 번의 구조화 응답으로 분류합니다. 저장 읽기 결과가 없으면 `OCR_REQUIRED`로 종료합니다.

원시값·제안값·정규화 값·인용·단위를 항목별로 검사합니다. 모호하거나 없는 값을 추측해 채우지 않으며 해당 항목은 `needs_review / missing`으로 남깁니다. 다른 정상 항목은 보존하고 개별 항목 오류로 유료 AI를 자동 재호출하지 않습니다.

## 3. 필요한 항목만 PDF 보완 읽기 B

A에서 확인이 필요하거나 미기재인 항목 중 **아직 확정하지 않은 1~50개 항목**을 선택해 B를 별도로 실행합니다. 문서 유형과 기본 A 결과가 먼저 있어야 합니다.

**B는 원본 전체 PDF를 OpenAI에 전송하며 추가 API 사용량이 발생합니다.** 선택 항목만 반환하도록 요청하지만, PDF를 해당 항목·페이지만으로 잘라 전송하는 방식은 아닙니다. 자동 실행하지 않으며 취소해도 이미 시작된 요청의 사용량은 발생할 수 있습니다.

B는 PDF에서 선택 항목을 다시 읽어 값·단위·페이지·인용을 반환합니다. OCR의 잘못된 철자와 다르다는 이유만으로 B를 버리지 않지만, 자료 접근·문서 버전·해시·대상 범위·형식·숫자 범위·단위 검사는 유지합니다. 표 항목은 기존 행의 항목명·날짜·거래 식별정보를 함께 전달하고 실제 같은 행을 찾아야 합니다. 행 번호나 같은 금액만으로 대응을 확정하지 않습니다.

## 후보 확인·저장·재실행

- A는 `case.extraction_a`·`extraction_a_revision`, B 실행별 결과는 `supplements`에 보존합니다. 현재 적용 후보 `case.extraction`과 분리합니다.
- A/B 후보의 원시값·제안값·검사 결과·단위·원문 위치를 확인합니다. 형식 검사를 통과한 후보를 원문 확인 후 선택하거나 직접 입력하고, 판단이 어려우면 선택을 보류합니다.
- B가 완료되어도 기존 값을 자동 교체하지 않습니다. A/B 값이 일치해도 검증 완료나 사용자 확인으로 승격하지 않습니다.
- `candidate_selections`·`candidate_selection_history`에 선택값·근거·원본 해시·A 버전·작업/실행 ID를 저장합니다. 후보 선택으로 자료 버전이 바뀌면 연결된 비교 묶음을 다시 불러와 입력을 확인해야 합니다.
- 디지털 인용의 `text_match`는 텍스트층 일치, `ocr_unverified`는 OCR 근거, `vision_unverified`는 B 판독 근거입니다. 어느 것도 원본 화면의 정확성이나 사용자 확인 완료를 뜻하지 않습니다.
- 원문 읽기·A 재추출·유형 변경은 이전 B·선택을 이력으로 보존하고 현재 적용에서 제외합니다. 다른 A 버전의 보완 결과를 섞지 않습니다. 기존 자료를 자동 재실행하지 않습니다.
- 취소·재개는 같은 원본·기본 결과·입력·설정에 한해 누적 호출 예산을 이어받습니다. 원본이나 기본 결과가 바뀌면 새 작업이 필요합니다.

운영 포트 `read_ocr(context, source, ocr_result_id)`는 호환 이름을 유지하며 저장된 로컬 읽기 결과와 페이지별 방식을 반환합니다. 접근 권한·source ID·문서 ID·버전·해시·결과 ID를 검증해야 합니다. B 전송 전에도 원본 접근과 취소 여부를 확인합니다.

기본 저장 위치는 `output/document-workspace/`입니다. [문서 대조](http://127.0.0.1:4190/compare)는 사용자가 확인한 값만 Python으로 비교하며 모델 호출이 없습니다. 법정 임금 자동 계산의 완료를 뜻하지 않습니다.
